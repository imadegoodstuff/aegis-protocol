# Aegis browser extension

The wallet's Protect / Spend surfaces as a side panel (Chrome, Edge, Brave;
Manifest V3). One password, one phrase, and the three panels the web wallet
renders — EVM, Bitcoin signet, Solana — with no MetaMask in the loop: gas is
paid by a key derived from the same phrase.

Status: builds and runs from source; not published to any extension store.
Unaudited, like the rest of this repository.

## Install (unpacked)

```sh
cd wallet && npm ci && cd ../extension
npm run build            # writes extension/dist
```

Then `chrome://extensions` → *Developer mode* → *Load unpacked* → pick
`extension/dist`. Click the Aegis icon to open the side panel (Chrome 116+;
on browsers without a side panel it opens as a tab).

## What happens

1. **Create or import** a 24-word phrase (BIP-39; 256 bits of entropy are
   required, the CCHS seed floor). It is encrypted with a password you choose
   — AES-256-GCM, key from PBKDF2-SHA-256 with 600 000 iterations — and the
   ciphertext is kept in `chrome.storage.local`. The password is never stored;
   the phrase is decrypted into memory on unlock and dropped on lock.
2. **Gas key.** `HKDF-SHA-512(seed, "aegis/ecdsa/fallback/v1")` — the same
   secp256k1 key the wallet already derives as the account's ECDSA fallback —
   is the fee payer; its address is shown at the top. Send it a little native coin on each chain you
   intend to use. It only pays fees; the protected assets sit in the hash-only
   CCHS account, so a quantum break of this key costs gas money, nothing more.
   The panels talk to it through a local EIP-1193 shim (`eth_sendTransaction`
   is signed in the page and sent to the public RPC), so every component is
   the same code the web wallet runs.
3. **Protect / Spend** work exactly as in the web wallet: the Protect button
   publishes the factory if needed, creates the account and moves the listed
   assets in; Spend builds the digest, signs one WOTS+ leaf, verifies locally,
   then sends.

Bitcoin signet needs no fee payer (fees come out of the account's own UTXO).
Solana moves still need a Wallet Standard wallet to pay fees; extension pages
cannot see other extensions' providers, so for Solana use the web wallet in a
tab.

## Security model, honestly

- Secrets in an extension page are as safe as the browser profile: anybody
  who can run code in the page, or read the profile's storage *and* guess the
  password, has the phrase. Prefer a dedicated profile. The vault slows a
  brute-force attempt down but a weak password is still a weak password.
- The extension requests only `storage` and `sidePanel`, plus `https://*/*`
  so it can reach public RPC endpoints and the mempool.space / Solana RPC
  APIs. It injects nothing into web pages and has no content scripts.
- CSP is `script-src 'self' 'wasm-unsafe-eval'`: the hash workers use
  WebAssembly (hash-wasm); no remote code, no `eval`.
- Nothing is bundled from a CDN; `npm run build` resolves every dependency
  from `wallet/node_modules` so the extension and the web wallet ship one copy
  of react, viem and the hash libraries.

## Layout

```
extension/
  public/manifest.json   MV3 manifest, side panel, CSP
  public/icons/          16/48/128 PNG (generated by scripts/icons.mjs)
  src/background.ts      opens the side panel on icon click
  src/vault.ts           AES-GCM / PBKDF2 vault over chrome.storage.local
  src/App.tsx            create / unlock / wallet screens; mounts the wallet's panels
  vite.config.ts         @wallet → ../wallet/src, single react/viem copy, fonts copied
```

`npm run typecheck` runs `tsc` over `src/` with the wallet's compiler options.
